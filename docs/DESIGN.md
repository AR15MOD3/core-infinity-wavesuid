# 设计：命令桥接、独立实例与平台投递

## 数据流

TelyinCore 正式工具调用 → 当前 Bot 的桥接器 → 经过实例认证的本机 HTTP → rover 与上游业务插件。
服务返回文本、任务状态或卡片链接；模型根据回执组织答复，需要图片时调用官方平台图片工具。
本插件不在工具内部固定角色台词，也不把图片链接等同真实投递成功。

## 代码与数据

- 插件包由所有 Bot 共享安装；选择、配置、账号及运行资源按 Bot 隔离。
- 独立版本化服务代码可以共享，服务进程、端口与数据租约不能共用。
- 桥接器与服务使用同一 bridge_version，校验 scope_id、实例哈希及自有进程状态。
- 配置须来自正式宿主作用域，缺身份时拒绝启用，不回退共享配置或其他 Bot 账号。
- 本机 Python 插件是可信代码；这些归属检查是误用保护，不宣称为恶意插件沙箱。

## 异步和回执

宿主通过 OwnedBlockingIO/WorkOwner 管理阻塞工作，提交前冻结 Bot、调用与会话归属。
服务保留长命令任务，及时返回已产生的回执和任务编号；后续查询按用户、会话和游标读取。
查询不重发原命令，超时不等同失败或成功，账号操作结果不明时禁止自动重试。
网页登录由本人打开链接授权，结果依据实际持久化事实；通知通过宿主系统钩子返回。

## 生命周期

create 不启动服务。start 校验正式配置后只创建自有进程，stop 排空自有工作并收尾进程树。
已有监听不视为自有服务。保留宿主生命周期 guard、后台工作证据和未排空失败，不接管外部进程。
Windows 使用自有 Job Object，POSIX 使用进程组；后者尚未完整实机验收。

## 卡片与缓存

PNG 在服务渲染。可复用帮助资料只存于本实例缓存，不混入用户账号查询。
媒体访问时间使用单独元数据；渲染签名基于源内容和渲染环境，不用文件访问时间替代内容指纹。
未知动态资源保守重渲染。QQ 发送使用官方 qq_send_image，遵守该 Bot 的白名单、媒体限制和真实协议回执。
